# 飞书权威知识库设计

**日期：** 2026-09-17  
**状态：** 已确认，待实施计划  
**范围：** 将 Picture Book Screenwriter Codex 插件从 WorkBuddy 资料库迁移到多人协作的飞书知识库。

## 背景与目标

原 WorkBuddy 专家团通过 `wiki-ingest` 从原始飞书知识库读取资料、归纳生成项目化知识文档，再写入 WorkBuddy 资料库。Codex 插件不能使用该资料库。

目标根节点为 `REPLACE_WITH_TARGET_ROOT_TOKEN`。多人可：

- 向原始飞书知识库上传资料；
- 发起知识库同步；
- 直接编辑 AI 生成的目标知识文档。

目标知识库中的人工编辑为权威内容，下一轮同步和绘本创作必须以其为准。任一用户机器上的本地文件只能是缓存，不能作为共享版本基线。

## 已确认决策

1. 目标飞书 Wiki 是知识消费的唯一权威；原始飞书知识库只作为 `wiki-ingest` 的输入源。
2. 目标内容使用飞书原生 `docx` 页面，而非原生 Markdown 文件。`docs +update --revision-id` 提供版本前提，可防止并发覆盖；Markdown 的 `+overwrite` 不提供等价的条件更新。
3. 人工修改优先于 AI 生成内容。发生语义冲突时，保留人工版本并创建待处理事项，绝不自动覆盖。
4. 多人同步通过远端协调锁串行化，并以每篇文档的 `revision_id` 作为最终并发保护。
5. 插件以每名编剧自己的飞书身份访问；插件不得依赖当前机器专用的 `D:\lark-cli` 路径。

## 总体架构

```text
原始飞书知识库（多人上传，输入）
          │
     wiki-ingest：抽取、归纳、产出候选内容
          │
feishu-knowledge-store：协调、读取、合并、条件写入
          │
目标飞书 Wiki（唯一权威）
          │
knowledge-loader：检索、版本取证、供编剧技能引用
          │
Picture Book Screenwriter：绘本创作
```

职责边界：

| 组件 | 职责 | 不负责 |
| --- | --- | --- |
| `wiki-ingest` | 枚举原始资料、提取内容、增量判定、归纳并生成项目化候选文档 | 写入 WorkBuddy、处理目标 Wiki 并发 |
| `feishu-knowledge-store` | 目标 Wiki 初始化、索引、锁、版本读取、三方合并、条件写入、冲突记录 | 原始资料的内容归纳 |
| `knowledge-loader` | 按创作请求检索并读取目标 Wiki、向创作注入引用与版本信息 | 写目标 Wiki |
| 编剧入口技能 | 调用知识加载、创作、在结果中记录实际引用版本 | 飞书 API 细节 |

## 目标 Wiki 信息架构

以目标根节点为父节点创建以下结构。系统页也存为 `docx`，而非本地状态文件。

```text
00_使用说明
  └─ AI知识库编辑说明
01_知识内容
  └─ {series_id}/{project_id}/
      ├─ 世界观
      ├─ 角色人设
      ├─ 内容规格
      ├─ 纠正登记册
      ├─ 创意特征台账
      ├─ 金句登记册
      ├─ 道具登记册
      ├─ 选题指纹与门禁规格
      └─ 参考索引
02_导航与日志
  ├─ 知识导航索引
  └─ 同步日志
99_系统控制台
  ├─ 同步索引
  ├─ 同步锁
  └─ 冲突待处理
```

`AI知识库编辑说明` 明确推荐路径是修改原始资料后再同步；直接编辑目标文档是允许的，并会被视为权威基线。它建议用户将人工补充标为“人工维护”，但系统不依赖该标记来保护内容。

## 远端控制面

`同步索引` 是共享清单。其正文只能包含固定标题 `# AI_KB_INDEX_V1` 和一个 `json` 代码块；代码块是完整 JSON 对象，不能使用自然语言或 Markdown 表格替代。每一个逻辑条目具有稳定键，而非以可修改的标题作为主键：

```json
{
  "key": "series/project/page_type",
  "doc_token": "目标 docx token",
  "wiki_node_token": "目标 Wiki 节点 token",
  "source_revisions": {"原始节点 token": "版本号"},
  "last_ai_revision_id": 42,
  "last_seen_revision_id": 45,
  "status": "published"
}
```

每篇知识页面末尾固定保留 `## 系统元数据（请勿编辑）` 标题和一个 `json` 代码块，至少包含 `key`、源节点 token、页面类型与最后一次 AI 写入 revision。`knowledge-loader` 不将该节注入创作上下文。控制文档或页面元数据也可能被人工误改，因此每次读取必须校验 JSON schema、校验条目 token 可读。无法校验时，系统停止写入、报告故障，并通过扫描 `01_知识内容` 页面末尾的系统元数据重建候选索引；重建结果需要用户确认后才替换控制文档。

`同步锁` 采用租约：运行实例读取锁文档并取得其 `revision_id`，仅在锁空闲或过期时带该版本号写入 `{run_id, holder, started_at, expires_at}`。版本冲突表示有其他实例抢先获得锁。长同步在阶段边界续租，结束时释放；租约过期才允许接管。

## 同步与合并协议

### 首次同步

1. 对 CLI 认证、源知识库读取权限、目标根节点读取/写入权限做只读预检。
2. 初始化 Wiki 目录、说明页和控制台；每个写操作后记录返回的 token 与 revision。
3. 全量运行 `wiki-ingest`，得到结构化候选内容。
4. 为每个候选内容创建一个 docx 页面，并写入远端索引、导航与日志。

### 后续同步

1. 获取远端租约，读取并验证远端索引。
2. 由 `wiki-ingest` 对原始资料做增量判定，找出受影响逻辑条目。
3. 对每个受影响条目取得三个版本：
   - **基线**：索引中 `last_ai_revision_id` 对应的历史 docx；
   - **当前版**：目标 Wiki 的最新 docx，含人工编辑；
   - **候选版**：以新原始资料归纳得到的知识页面。
4. 执行三方合并并以当前版 `revision_id` 调用 `docs +update`。
5. 成功后更新远端索引、导航和同步日志；写入失败或冲突不得伪造成功状态。

### 人工优先规则

| 情况 | 行为 |
| --- | --- |
| 仅原始资料变化 | 用候选版更新目标文档。 |
| 仅人工编辑 | 保留当前版；作为下一轮创作的直接依据。 |
| 两者变化且无语义冲突 | 保留人工变化，同时纳入原始资料新增内容。 |
| 两者变化且存在语义冲突 | 人工内容胜出；不覆盖文档，在“冲突待处理”登记来源变化、差异与文档链接。 |
| 写入遇到 revision 冲突 | 重新读取最新人工版本，重新合并；仍无法安全合并则登记冲突并停止该条目。 |

系统不以“AI 之前写过什么”推翻人工内容。历史版本仅用于找出人工增量，绝不作为覆盖依据。

## 读路径与创作取证

`knowledge-loader` 按项目名、角色、主题、年龄段等检索 `01_知识内容`。它只读目标 Wiki，不读取运行者本地缓存作为事实来源。它将每次引用的 `logical_key`、`doc_token`、`revision_id` 写入创作产物 metadata，以支持复现与审计。

状态为 `needs_review` 的条目仍可被读取，但编剧入口必须显示其存在未处理冲突；不可将其描述为已完全验证的定稿知识。

## Lark CLI 与身份约束

`D:\lark-cli\lark-cli.exe` 是本机兼容路径，不是插件交付条件。运行时按以下顺序解析 CLI：

1. `LARK_CLI_PATH` 环境变量；
2. PATH 中的 `lark-cli`；
3. Windows 兼容回退路径 `D:\lark-cli\lark-cli.exe`。

每名使用者先用自己的身份完成 `lark-cli auth login`，并获得源 Wiki 读权限和目标 Wiki 写权限。默认以 `--as user` 操作，从而保留实际操作者身份。

写入实现应使用 `docs +create --parent-token <wiki-node> --doc-format markdown` 创建 docx，以及 `docs +update --revision-id <revision>` 更新既有 docx。禁止将无条件的 `markdown +overwrite` 用于共享权威页面。

## 故障策略

| 故障 | 处理 |
| --- | --- |
| CLI 不存在、认证失效、权限不足 | 阻断本次同步，给出具体预检失败项。 |
| 目标节点不可读取 | 阻断；不得创建替代知识库。 |
| 同步锁被持有 | 不执行同步，返回持有者与租约到期时间。 |
| 索引损坏 | 停止写入，扫描重建候选索引并要求确认。 |
| 单条文档冲突 | 保留当前 Wiki 文档，写入冲突队列，继续其他独立条目。 |
| 网络或短暂服务错误 | 有限退避重试；不重试权限、参数和配额错误。 |
| 目标 Wiki 不可用 | 创作可以使用最近一次经确认的本地缓存，但必须标明离线与缓存版本；同步一律失败。 |

## 迁移与验收

迁移不导入 WorkBuddy 资料库作为权威来源。以原始飞书知识库执行一次全量同步建立新的目标 Wiki；旧 WorkBuddy 数据仅可作为人工核对参考。

验收必须覆盖：

1. 首次全量同步生成项目化页面、导航与控制台。
2. 原始资料无变化时，重复同步不改写知识页面。
3. 原始资料变化时，只更新受影响页面。
4. 人工编辑后，未发生源变更时同步不改写该页面。
5. 人工编辑与源变更并发时，人工内容不会丢失；冲突会进入队列。
6. 两名用户并发发起同步时，只有一人取得锁；条目写入仍受 revision 防护。
7. 创作产物可列出实际引用的飞书文档 token 与 revision。

## 非目标

- 不复刻 WorkBuddy 团队运行时、hooks 或 WorkBuddy 资料库。
- 不做自动双向同步到原始资料库。
- 不尝试阻止人类编辑目标 Wiki；系统只负责将其视为权威并安全处理。
- 不将本地 staging、manifest 或缓存作为多人共享的权威状态。
