# Enforcement Levels

`plugin-contract.json` is a public plugin boundary and validation input. It is
not loaded by the runtime execution path and does not act as a sandbox.

The levels below describe where a guarantee actually lives.

- `runtime_required`: execution rejects or blocks an invalid operation.
- `script_checked`: a script validates required inputs, but cannot prove user
  intent or prevent an authorized caller from supplying valid values.
- `prompt_only`: behavior depends on the model following Skill instructions;
  there is no host-level prevention.

A `runtime_required` level only applies when its owner script is in the execution path.
Whether a Skill chooses to invoke that script remains prompt-driven unless
host policy enforces the call.

| Credential arguments are refused on the command line | `runtime_required` | `skills/jev-decision-runtime/scripts/jev_runner.py` | A flag one of whose whole `-`/`_`-separated words names a secret (`--api-key`, `--openai-api-key`, `--token`, `--secret`, `--password`, `--db-credential`), or whose name ends in `key` (`--openai-key`, `--my-key`, `--mykey`), is rejected before the parser runs, so the gate's own refusal quotes the flag name only; the check reads the flag name only, so a path that merely contains the word `key` still passes, a qualifier that names an ordering, relation, or cache key (`--sort-key`, `--primary-key`) or an ordinary word that merely ends in those letters (`--monkey`) is not a credential, and a count such as `--max-tokens` is not the secret `--token`. This vocabulary reads shapes, so it cannot be complete — `--tokens` and `--api-keys` are not among them — and what covers the rest is `parse_known_options` (next row). argparse still prints the value of a *recognised* option whose value it rejects, so a credential must never be put on the command line in the first place. |
| An unrecognised argument is refused by name, not by value | `runtime_required` | `skills/jev-decision-runtime/scripts/jev_runner.py` | All four entry points (`jev_runner.py`, `relevance_cli.py`, `screening_cli.py`, `compare_cli.py`) parse through `parse_known_options`, which refuses every argument their parser does not declare and reports it by flag name — a placeholder for a bare positional — instead of quoting what it carried the way argparse's own `parse_known_args`-plus-error path does. Abbreviations are off too (`allow_abbrev=False`), so a shortened flag is reported by name rather than as an ambiguity that quotes its value, and `jev_runner.py` refuses an unknown subcommand by placeholder before argparse can print `invalid choice`. What is *not* covered: a value a recognised option rejects is still echoed by argparse, and the script's own error text quotes whatever it was given (an unreadable `--request` path, say). A credential therefore belongs in the environment, never on the command line. |

| Jev is only called after the user chooses it | `prompt_only` | Entry Skill instructions | There is no host-level prevention. |

| A screen never re-sends a record it cannot read | `runtime_required` | `skills/knowledge-loader/scripts/relevance.py` | A request, result, or pending record that exists but does not parse — or parses to something other than an object — a result that does not satisfy the contract for its batch, and a pending record whose `attempt_status` is not one of the two (`pending`, `failed`) that leave nothing open behind them, all keep their batch out of the screen instead of paying for it again. |
| A stored result is reused only for the request it answered | `runtime_required` | `skills/jev-decision-runtime/scripts/jev_runner.py` | `result_answers_request` compares the result's own `trace.input_sha256` with the request in hand, so a record written before an edit — or one that never recorded which request it answered — is never routed from, by `resume` or by the screening path. |
| A screen that stops on a record it cannot vouch for names it | `runtime_required` | `skills/knowledge-loader/scripts/relevance.py` | Every record that keeps a batch out of the screen is reported as `blocked_records` (operation id, path, and reason), so a stopped run is actionable instead of stopping silently in the same place on every re-run. |

| A failure never produces a clear verdict | `runtime_required` | `skills/pre_output-baseline/scripts/screening.py` | No answer, an answer no rule can band, and a routing error all become `runtime_failure`, which carries no probabilities and can never skip the plain-LLM review. |

| The pre-screen entry point refuses a draft it cannot read | `runtime_required` | `skills/pre_output-baseline/scripts/screening_cli.py` | A file whose page table parses to no row and an authority bundle that cannot be read as one both exit with a JSON error before any request is sent; a draft whose pages are all wordless is reported as `item_count = 0` with its own warning instead of as a pass. |
| The pre-screen CLI reports its coverage instead of a bare exit code | `script_checked` | `skills/pre_output-baseline/scripts/screening_cli.py` | The report carries `catalog_gap`, `may_skip_llm_review`, the `summary` ratios, `blocked_records` and `warnings`, and the command still exits 0 when every dimension waited for the credential or failed — so the verdict lives in the report, and whether the pre-screen should run at all remains prompt-driven. |
| Threshold calibration status | `prompt_only` | `skills/pre_output-baseline/references/calibration-samples.md` plus the Skill instructions | The scripts cannot prove the thresholds were calibrated on Chinese samples; only a human-accepted measurement moves an operation from `experimental` to `calibrated`. |
| The two attested case identity fields must match | `runtime_required` | `skills/jev-decision-runtime/scripts/comparison.py` | `benchmark_case_id` must be attested by a trace of this run and `policy_version` must be one the run actually ran; a field that is missing or null on either side is a hole rather than a match, and any difference reports `comparable: false` with one reason per field. |
| The four declared case identity fields are compared as declared | `prompt_only` | `skills/jev-decision-runtime/scripts/comparison.py` | `input_revision_vector_sha256`, `draft_sha256`, `rule_version` and `artifact_params` are copied from the plain-LLM declaration, so the report compares them pairwise and marks them declared-only in `identity_attestation`; nothing in the run directory can catch a wrong declaration, which is why the report says so rather than claiming it verified six fields. |
| The plugin never reads the CC Switch database | `runtime_required` | `skills/jev-decision-runtime/scripts/comparison.py` | `load_llm_usage()` accepts only a manual entry whose `source` is `cc-switch-manual-entry` or `manual`; a `cc-switch` database path or any other source string is refused, so the report cannot silently start depending on private storage. |
| The comparison report export directory | `runtime_required` | `skills/jev-decision-runtime/scripts/compare_cli.py` | The directory must be absolute and outside the plugin, and the export path additionally requires `--plugin-root`; both are refused before anything is written. |
| Command-line credential arguments are refused | `runtime_required` | the same `reject_credential_arguments` and `parse_known_options` as `jev_runner.py` | A flag one of whose whole `-`/`_`-separated words names a credential, or whose name ends in `key` with the qualifier separated or glued on (`--openai-key`, `--mykey`), is rejected before the parser runs, except where that qualifier names an ordering, relation, or cache key (`--sort-key`) or the word merely ends in those letters (`--monkey`); a count such as `--max-tokens` is not one of them. Every other unrecognised argument — flag, abbreviation, subcommand, or bare positional — is refused by `parse_known_options` by name rather than by value, and abbreviations are off so a shortened flag cannot be reported as an ambiguity quoting its value. argparse still echoes the value of a *recognised* option it rejects, and the script's own error text quotes what it was given, so a credential must never be put on the command line in the first place. |
| Credential waits and path switches stay out of the performance sample | `script_checked` | `skills/jev-decision-runtime/scripts/comparison.py` | Traces in `UNMEASURED_STATUSES` and traces with `fallback_used: true` are dropped before the metrics are folded, but the report still names the operations it did measure; whether a user reports a path switch honestly still depends on the trace. |
| The trace records the verdicts the operation itself decided | `script_checked` | `skills/jev-decision-runtime/scripts/jev_runner.py` | `run_operation(verdicts=…)` writes the operation's own `screened_clear_count` / `escalated_count` into the trace, so the report's escalation rate is the rate the run decided; a hook that raises or answers with something that is not two counts, and a batch that never settled, record the zero pair, which reads downstream as "nothing here to calibrate from" rather than as "everything was clear". The comparison report counts a succeeded trace that carries that zero pair as `traces_without_verdicts` — the `resume` entry point has no operation routing to hand the runner — and withholds `eligible_for_calibrated` while one is present, because those two counts cover only the batches that recorded theirs: the share may be off in either direction, which may not be read as "cleared enough to stop re-checking". A trace written by a build older than this one still reads as zeros, which is why the row is `script_checked`. |
| One comparison report describes one run | `runtime_required` | `skills/jev-decision-runtime/scripts/comparison.py` | A run directory whose traces name more than one `run_id` is refused (`comparable: false`) with the run ids listed, and each run's own numbers stay visible in `jev_operations`; the declared `benchmark_case_id` must be attested by a trace of that run, and a directory holding no trace, only traces naming no case id, or only traces of other cases records a reason instead of comparing a measurement with an unchecked declaration. |
| The report is exported only on an explicit user request | `prompt_only` | Skill instructions | Calling the CLI directly with `--output-dir` is not blocked; only the Skill keeps the default to the conversation. |
| Calibration status changes only by hand | `prompt_only` | `references/comparison-procedure.md` plus the Skill instructions | The script only suggests `keep_experimental` / `review_thresholds` / `eligible_for_calibrated`; nothing stops a person from editing the policy file. |

Use host-level permissions, approval prompts, or hooks when a guarantee must
hold even if a model ignores the Skill instructions.
