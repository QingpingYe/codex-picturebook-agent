# Changelog

## [Unreleased]

### Added

- Codex-native picture-book editorial workflow and baseline slots.
- Feishu authoritative knowledge synchronization and retrieval.
- Craft benchmark, project red lines, Wiki lint, and optional Lexile gates.
- Gated illustration workflow with structured prompt payloads.
- Self-contained HTML preview and illustration asset registry.
- Workspace-first Feishu config discovery, config status, and read-only authority CLI.
- Portable Feishu config discovery for project subdirectories, user directories, and shared plugin distribution.
- Jev-assisted decision layer infrastructure: an explicit execution choice gate, `pb-decision-context-v1` propagation, credential waiting and recovery points, a single-holder execution lease, atomic terminal results, decimal cost estimation, and benchmark case alignment.
- `knowledge_relevance`: authority pages are chunked, hard-constraint chunks are marked unfilterable, soft candidates are recalled, and Jev screens those candidates; the reduced evidence bundle feeds the ordinary model context while the unfiltered revision vector stays available to the dependency lock.
- `text_quality_prefilter`: every active red line and the five per-page text-quality dimensions are pre-screened by Jev, with Chinese calibration samples and a threshold calibration tool.
- `text_quality_prefilter` now has its operator entry point: `skills/pre_output-baseline/scripts/screening_cli.py` screens a draft's page table against the authority red-line catalog, writes the escalation package for the plain LLM, and reports the ratios, `catalog_gap`, `blocked_records` and warnings instead of leaving the orchestration reachable only from tests.
- Side-by-side comparison report for the two execution paths: case-identity comparability gate, Jev traces merged with manually entered plain-LLM usage, per-operation calibration advice, and an export that only happens on an explicit request.

### Changed

- Split WorkBuddy reference material out of the Codex plugin runtime.
- Stage workflows now represent approval and revision as exclusive outcomes.
- Revision rounds create new runs and rerun preflight, collision, and QA checks.
- v1 run manifests require explicit migration.
- The entry workflow now opens with an `## Execution Choice Gate` before intent classification on every top-level request.

### Fixed

- The request that leaves the client now carries only the three fields the SystemOne endpoint declares (`model`, `state`, `questions`): the first real call returned `api_usage_error: Invalid request`, because the runner's own envelope (`run_id`, `operation`, `policy_version`, `benchmark_case_id`, `context_refs`, …) travelled with it and the endpoint validates its top-level fields strictly. The envelope still lives in `request.json` and in the identity hashes, so resume, reuse and the case fingerprint are unchanged, and a unit test now pins what goes on the wire.
- The machine-readable contract now states that a `project_authority` finding blocks the confirmation gate at any severity (`any_finding_blocks_confirmation`), matching the runtime, where promotion forces `severity="FAIL"` and a later judgment can no longer soften it.
- A literal red-line hit that the model cleared now reaches the plain LLM instead of only the report's counter: spec §9.4 sends that disagreement for review, so the conflict becomes an escalation entry (`reason: proxy_conflict`) for every window asked about that rule, `summary.escalated_by_proxy_conflict` counts it, and the pre-screen CLI reports nothing as skippable while a conflict stands — a calibrated run can no longer skip the item the two signals disagree on.
- The comparison report's Jev column is no longer structurally zero: the shared runner's `verdicts=` hook writes the `screened_clear_count` / `escalated_count` each operation really decided into its trace (previously `trace_for` wrote 0, which left the escalation rate and the calibration advice meaningless). Calibration advice is read per operation from that operation's own counts, an operation this run never measured gets no advice, `knowledge_items_entered` and `quality_items_entered` each come from their own operation's escalation count, a run directory whose traces name more than one `run_id` is refused (`comparable: false`) with the run ids listed instead of silently summing two runs, and a declared case id no trace can attest records a reason along with the trace counts. A succeeded trace that never recorded its counts — the `resume` entry point has no operation routing to hand the runner — is reported as `traces_without_verdicts` and withholds `eligible_for_calibrated`, because those two counts cover only the batches that recorded theirs: the share may be off in either direction rather than merely thin.
- The command-line credential gate matches the shape of a flag rather than a fixed list of spellings: `--openai-api-key`, `--access-key`, `--password` and `--openai-key` are refused the same way `--api-key` is. The check reads the flag name only, as whole `-`/`_`-separated words: a path containing `key` still passes, a qualifier that names an ordering, relation, or cache key (`--sort-key`, `--primary-key`) or an ordinary word that merely ends in those letters (`--monkey`) is not a credential, and a count such as `--max-tokens` is not the secret `--token` — while a qualifier glued onto the `key` (`--mykey`) is refused with the separated `--my-key`. Because no vocabulary of spellings is complete, the four entry points now parse through `parse_known_options` as well: an argument the parser does not declare is refused with its flag name — a placeholder for a bare positional — instead of the value argparse would have echoed. That is the guarantee the enforcement rows state; argparse still echoes the value of a *recognised* option whose value it rejects, so a credential still belongs in the environment rather than on the command line.
- The comparison report's case attestation no longer reads another case's traces: the declared `policy_version` is checked against the operations only this case's traces name (a directory that also holds an earlier case's trace used to attest a version this run never used), and a directory holding this case beside another one now names `benchmark_case_id` among the fields it verified instead of recording it as declared-only.
- The four entry points no longer let an abbreviated flag or an unknown subcommand quote what was passed: abbreviations are off (`allow_abbrev=False`), so `--r=SUPER-SECRET` is reported by name instead of as an ambiguity carrying the value, and `jev_runner.py` refuses an unrecognised command by placeholder before argparse can print `invalid choice`.
- Knowledge loading now rejects page revisions behind the remote index, marks page-ahead evidence as `index_synced=false`, and prevents unsynced reads from replacing the last confirmed cache.
- Terminal stage-run validation now evaluates run-level status and outcome without shadowing by stage fields.
- `knowledge_relevance` now reuses a stored terminal result only when it records the request it answered, so an edited authority page is never routed on the previous edit's verdicts; the record that keeps a batch out of the screen is reported as `blocked_records`, and a failed batch's pending record is dropped under the operation lease instead of after it.
- A screening batch keeps its record instead of paying again when the file on disk exists but cannot be read as one: a `result.json` that fails to parse or parses to a non-object is now reported as `unreadable_result` rather than treated as no record, and a pending record whose `attempt_status` is neither a waiting call nor a settled failure is reported as `unreadable_pending`. A result that names no request at all is reported as unreadable rather than stale.
- A settled operation clears the run-level `pending_call` in `decision-context.json` only when no other operation is still waiting, so a second batch's ambiguous call stays named for every reader of the context.
- A semantic judgment can no longer downgrade a literal project red-line hit to PASS: proxy hits and confirmed violations are now separate sources, and only a confirmed final review produces a blocking finding.
- The comparison report's Jev-assisted column no longer shows only the pre-screen's own bill. spec §10.3 asks for the escalated items' plain-LLM calls as their own row, so the manual usage entry now takes an optional `upgraded_llm_usage` block (request count, input/output/cache tokens, elapsed time, estimated cost), the report renders those alongside the plain-LLM column's, and `total_estimated_cost_usd` / `total_elapsed_ms` give each path its total — a half-measured path keeps the total `null` instead of reading as the smaller half, a misspelled key in the block is refused instead of reading as "not measured", and a cost written as a JSON number is refused with the same quoting hint as the top-level one.
